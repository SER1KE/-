# DTEK Odesa → Telegram: уведомления об отключениях

Настройка проекта:
- Город: Одесса (`м. Одеса`)
- Улица: Щоглова
- Дом: 20/1 (корпус 1)
- Очередь: 2.1
- Предупреждение о плановом отключении: за 60 минут
- Авария: уведомление при обнаружении активного отключения в опубликованных данных ДТЭК
- Восстановление: отдельное сообщение, если ДТЭК явно показывает, что ранее обнаруженное аварийное отключение закончилось
- Повторные сообщения подавляются через `state.json`

## Важно перед запуском

Это подготовленный проект, а не уже работающий бот. Данные ДТЭК нужно проверить на реальном ответе сайта перед тем, как полагаться на уведомления. Сайт может менять формат, блокировать автоматические запросы или не публиковать отдельные аварийные события.

ДТЭК предупреждал, что в доме Щоглова, 20 схема электроснабжения сложная и разные квартиры могут относиться к разным очередям. В проекте выставлена запрошенная очередь **2.1**, но это не подтверждение очереди именно вашей квартиры.

## 1. Создать Telegram-бота

1. В Telegram откройте `@BotFather`.
2. Создайте бота командой `/newbot`.
3. Сохраните токен у себя. **Не отправляйте его в чат и не добавляйте в файлы проекта.**
4. Напишите своему боту любое сообщение, чтобы открыть диалог.
5. Получите свой chat ID безопасным способом (инструкция ниже).

## 2. Добавить секреты в GitHub

Откройте репозиторий `SER1KE/-` → Settings → Secrets and variables → Actions → New repository secret.

Добавьте:
- `TELEGRAM_BOT_TOKEN` — токен от BotFather
- `TELEGRAM_CHAT_ID` — ваш личный chat ID

Не публикуйте эти значения и не вставляйте их в исходный код.

## 3. Загрузить файлы

Распакуйте архив и загрузите **содержимое папки** в корень репозитория `SER1KE/-`, сохранив структуру каталогов. Затем откройте вкладку Actions и разрешите запуск workflow, если GitHub попросит.

## 4. Проверить вручную

Вкладка Actions → `DTEK Telegram notifier` → Run workflow.

Первый запуск только проверит доступность данных и создаст начальное состояние. Чтобы не прислать ложное уведомление о восстановлении, бот не отправляет сообщение о восстановлении, пока ранее не было зафиксировано активное аварийное отключение.

## Частые ограничения

- GitHub Actions запускает cron не строго по минутам; возможны задержки.
- DTEK может отвечать 403/429 или менять структуру данных.
- Предупреждение за час возможно только если ДТЭК заранее опубликовал время начала.
- Аварийное уведомление возможно только если состояние аварии присутствует в данных, которые отдаёт ДТЭК.
- Если адрес не находится или найденная очередь не совпадает с 2.1, остановите workflow и уточните данные на официальном сайте ДТЭК.

Официальная страница: https://www.dtek-oem.com.ua/ua/shutdowns
